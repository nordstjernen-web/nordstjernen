# Source-code and feature review — May 2026

Snapshot of where Nordstjernen sits at v0.4.0, ~27 kLOC of C, vs.
the 2026 browser landscape. Written from a read of `src/`,
`README.md`, `NORDSTJERNEN.md`, and a sweep across the JS, CSS,
layout, net, and security layers. Not a roadmap rewrite — a punch
list of what the code currently is, where it's strongest, and the
two or three places where focus would yield the biggest payoff.

## What's actually in the box

### Engine surface
- **HTML5 via lexbor.** Single parser, gumbo cross-check has been
  removed. Solid foundation.
- **CSS engine — ~3.3 kLOC, ~80 properties, two backends.**
  Own selector engine plus optional lexbor matcher. Supports
  flex (`src/layout.c:1839+`), basic grid (track sizing,
  fixed/percent), `@media`, `@supports`, linear gradients, border
  radius, box shadow. No `@keyframes`, no `@font-face`, no
  transitions, no transforms, no `@import` follow-through. Floats
  and `position: absolute|fixed` are skipped (see
  `layout.c:227` / `:1246` — `style_is_absolute_or_fixed` returns
  FALSE early). Only `position: relative` and `sticky` (treated
  as relative) move boxes. This is the biggest *visual* fidelity
  gap on real-world pages.
- **JavaScript via quickjs-ng v0.14.0.** Interpreter only (no
  JIT). `src/js.c` is 8.2 kLOC of bindings. Surface is genuinely
  broad: DOM read+write, `style`, `classList`, event
  bubbling+capture, `addEventListener`, `fetch`, `XMLHttpRequest`,
  `localStorage` persistent + `sessionStorage` in-memory,
  `setTimeout/Interval`, `MutationObserver` (no-op),
  `IntersectionObserver`, `customElements`,
  `history.pushState/replaceState`, `matchMedia`,
  `getComputedStyle`. Bundled jQuery 3 shim. Promises/microtask
  drain after every JS entry. Modern APIs (geolocation, clipboard,
  permissions, Notification, navigator.share) are stubbed to
  rejected / denied — a deliberate, defensible choice.
- **Networking via libcurl.** Cache partitioned by top-level
  site, dynamic HSTS with bundled preload list, mixed-content
  blocking, CSP subset (`script-src`/`style-src`/`img-src`/…
  without nonce/hash/strict-dynamic), SOP/CORS gate on
  fetch+XHR, per-origin fetch throttle, libcurl-enforced TLS
  + redirect cap (10) + 60 s per-request deadline.
- **Charset detection via uchardet**, **URL parsing via lexbor's
  URL module**, **HTTP cache** under `$XDG_CACHE_HOME`, **image
  decode via Wuffs** (PNG/GIF/BMP/JPEG) → GDK-Pixbuf fallback
  → librsvg for SVG.
- **Media:** `<video src="…webm">` with libvpx VP9, first-frame
  paint only. No audio. No MSE. YouTube-the-site explicitly out.
- **Headless mode:** `--headless --dump=<text|dom|layout|png|pdf>`
  drives the engine off the main loop. Genuinely useful.

### Chrome
- GTK 4 + libadwaita-aligned. Tabs (since the 2026-05-11 reversal),
  Back/Forward/Reload/Stop/URL bar, bookmarks popover, Find on
  Page with match counter, zoom Ctrl+/-/0, Render-DOM-Raw-Layout
  view dropdown, right-click context menu, smart-bar
  (bare-word → DuckDuckGo), per-window OS process split.
- Keybindings: Ctrl+N/T/W/L/R/F/+/-/0/P, Ctrl+Shift+J for the
  JS console, Alt+Left/Right for history, Escape stops.

### Security posture (genuinely strong for the LoC count)
- Linux Landlock filesystem sandbox, default-deny libseccomp
  allow-list syscall filter, refuses to run as root /
  Administrator, PIE / RELRO / stack-protector-strong /
  stack-clash / CET / `_FORTIFY_SOURCE=2` / NX stack.
- No JIT (QuickJS is interpreter), no WebGL/WebGPU/WebRTC/SW/
  WebUSB/WebBluetooth/WebHID/WebMIDI/MSE/EME — entire
  exploit-prolific surface is foreclosed by construction.
- HSTS preload bundled (`src/hsts_preload.h`, 128 lines —
  much smaller than Chromium's, worth checking coverage).
- DNT: 1 sent (`net.c:1299`) — debatable in 2026 since most
  trackers ignore it and it's a fingerprinting bit, but
  harmless.

## What's missing vs. "a 2026 browser people read with"

These are the gaps that bite a user who installed it expecting to
read the web. Ordered by how often a real page hits them.

1. **No `position: absolute` / `fixed` / `float`.** Pages that
   use sticky headers, modal overlays, sidebar floats, or
   "fixed nav" will mis-render. This is a single hot spot in
   `layout.c` — `style_is_absolute_or_fixed` short-circuits to
   FALSE. Implementing a containing-block walk + a separate
   absolute-position pass is the highest-value layout work
   left, by a wide margin.

2. **No text selection on the rendered page.** Roadmap-tracked
   (NORDSTJERNEN.md Phase 6 remaining), but for a browser whose
   pitch is "read the web," not being able to select-and-copy a
   sentence is the single most-felt regression vs. every other
   browser. Higher-impact than any new CSS feature.

3. **No downloads.** A click on `Content-Disposition: attachment`
   or a `.pdf` / `.zip` link has no save-target. There's no
   `nd_download_*` anywhere. Tier-1 reading-list pages don't hit
   it, but anyone using the browser as their daily driver does
   within the first hour.

4. **No image rendering for non-replaced `background-image`.**
   Hacker News upvote arrows, badges, sprites, decorative
   backgrounds — all currently empty boxes. The known HN gap
   is explicitly listed in NORDSTJERNEN.md; the fix generalises.

5. **No CSS transitions / `@keyframes`.** Pages that fade-in or
   slide nav drawers either pop or stay in their pre-animation
   state. Less critical for *reading* pages, but it's how a lot
   of modern pages signal interactivity.

6. **`@font-face` and webfont loading.** Sites without it
   fall back to Pango defaults, which is fine for legibility but
   visually identifies the browser instantly. Not a high
   priority for a reader, but it's the cheapest tier of "looks
   normal."

7. **Forms surface is thin.** Phase 8 work: `<form>` GET/POST
   exists but SameSite cookies, full `<select>`/`<textarea>`
   editing, file inputs, and `<input type=...>` validation
   semantics aren't all there. Real-world login pages will
   trip on edge cases.

8. **No accessibility tree.** `ARIA` attributes are parsed as
   normal attributes but nothing exposes them to AT-SPI. For a
   GNOME-aligned browser this is a future Circle blocker.

9. **No printing-from-page beyond Cairo PDF dump.** Print
   dialog is hooked (`win.print`) but page setup, headers/
   footers, and "Print to system printer" via GtkPrintOperation
   would round it out.

10. **JS DOM events have keyboard/focus events shipped, but no
    `input`/`change`/`focus`/`blur` on `<input>`/`<textarea>` yet**
    (Phase 7 remaining). Lots of modern pages gate UI behind
    `input` events.

## What Nordstjernen does *better* than the big browsers in 2026

Not flattery — these are real differentiators worth leaning on.

- **Audit-in-an-afternoon size.** 27 kLOC is the entire renderer
  + JS bindings + chrome + sandbox. No competitor is within two
  orders of magnitude. This is the *product story*.
- **No JIT, no MSE, no WebGL/WebGPU, no SW, no extensions.**
  The exploit categories that dominate Chrome / Firefox CVE feeds
  do not exist here.
- **Honest sandboxing on Linux.** Landlock + seccomp default-deny
  is unusual for a third-party browser — most ship namespace +
  seccomp permit-list and call it a day.
- **No telemetry, no update pinger, no Safe Browsing fetch.**
  In 2026 this is genuinely rare. Even LibreWolf phones home for
  updates.
- **Reproducible build, single binary, MSYS2-buildable on
  Windows.** The kind of release artefact a security-curious
  user can actually verify.
- **Headless renderer with text/dom/layout/png/pdf dumps.**
  This is a niche feature in mainstream browsers and a first-class
  one here — interesting for `lynx`/`w3m`-style use cases and for
  CI scrape-with-real-rendering jobs.

## Where to focus next — recommendation

Pick **two** of these, ship them, then re-evaluate. Don't fan out.

### Highest-leverage, in priority order

1. **Text selection + copy on the rendered page.** Single biggest
   usability win. The plan in `NORDSTJERNEN.md:142–172` is sound;
   it's blocked on "someone do it," not on design. ~600 LoC of
   work in `paint.c` + `main.c` + a new `selection.c`.
2. **`position: absolute` and `fixed`.** Single biggest *visual*
   correctness win. Sticky headers and overlay modals are the
   feature most pages assume works. ~400 LoC in `layout.c` for a
   containing-block walk + second positioning pass.
3. **`background-image` painting on non-replaced boxes.** Hacker
   News, GitHub, most CSS-icon UIs depend on it. The image
   pipeline already exists (`image.c`); it just needs to be
   driven from `paint.c` for backgrounds. ~150 LoC.
4. **Downloads.** Honour `Content-Disposition`, route through
   `xdg-desktop-portal` file picker on Linux (and the GTK native
   chooser fallback). Small new file `src/download.c`, plus a
   hook in `nd_on_fetch_done`. Aligned with the "GNOME-native
   browser" positioning.

### Strategic, but slower

5. **Right-side of Phase 7 (input/change/focus/blur events,
   editable `<input>`).** Required for any non-trivial JS site.
6. **SameSite + third-party cookie default.** Already in the
   roadmap; finish it so the cookie story is end-to-end.
7. **CSS `@font-face`.** Cheap; visual fidelity boost on most
   modern sites.
8. **Accessibility tree via ATK / AT-SPI 2.** Required for
   GNOME Circle and a meaningful claim of "GNOME-native."

### Things to *not* do, even though the temptation will surface

- **Don't ship a service worker / push / background sync API.**
  The threat-model and LoC budget both forbid it. The README's
  competitive pitch is "we don't have this." Stay honest.
- **Don't add MSE for YouTube.** Same reason — the engine cost
  is enormous and the maintenance cost is permanent. Direct
  WebM is the right ceiling.
- **Don't add WebExtensions.** Even a stub. Once the extension
  surface exists, the audit-in-an-afternoon story dies. Users
  who want adblock can put their tracker filter list in
  `data/compatibility-css/` (and a future host-block file).
- **Don't add a JIT to QuickJS.** "No JIT" is the security
  pitch.
- **Don't add a tab session-restore-on-disk.** Already deferred
  for privacy reasons; keep it deferred.
- **Don't add localisation infrastructure.** English-only is
  documented as a constraint. Adding gettext is a multi-kLOC
  irreversible commitment.

## Code-quality observations

- `src/js.c` at 8.2 kLOC is the largest file by far. The
  `NORDSTJERNEN.md` rule "all JS bindings in one file" is being
  obeyed and the file is still navigable. Don't split it.
- `src/main.c` at 3.8 kLOC is becoming a kitchen sink (window
  setup + actions + key handling + URL bar + input editing +
  context menu + bookmark watch + tab strip). Worth keeping an
  eye on — once it crosses 5 kLOC, an extraction (e.g.
  `urlbar.c`, `tabs.c`) becomes worth the friction.
- `src/css.c` at 3.3 kLOC and `src/layout.c` at 2.9 kLOC are
  about right for what they do.
- No-comments policy is being followed cleanly. The single
  one-line file-header comment style is the only comment shape
  in the tree. Good.
- `nd_js` teardown leaks are still on the backlog
  (`NORDSTJERNEN.md` ideas-backlog item) — production builds
  paper over them with `NDEBUG`, but the underlying object
  leak is real and should be fixed before any long-running
  daemon-style use case lands.

## TL;DR

Nordstjernen is a usable text-web reader with an unusually
strong security posture and a uniquely small attack surface. The
**three** things between "neat tech demo" and "I'd actually use
this daily" are:

- text selection on the rendered page,
- `position: absolute` / `fixed`,
- and downloads.

Everything else can wait.
